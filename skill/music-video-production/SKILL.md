# Stagecraft — Music Video Production

Turn an existing recording into an intentional music video while keeping the song, characters, edit decisions, and delivery evidence recoverable. This skill contains a portable production method, local validation helpers, and an authorized Smart Home Strike learning example. It does not grant access to that project's accounts or permission to spend, upload, publish, or contact anyone.

## Start with the production that actually exists

Recover the current brief, chosen song/master, authoritative cut, original sources, outstanding notes, and ownership/holds before rebuilding. If there is no project, establish the song, concept, cast, intended audience, delivery format, editor, available tools and spending boundary. Carry forward existing authorization; ask only for material missing choices. Never create an open-ended Goal or automation merely because the task is large.

Keep one small project state file with the active revision, next action, pending generation IDs, actual spending observations, approved sources and unresolved decisions. A restart must reconcile pending submissions before generating again. A handoff or pause means preserve state and stop.

## Goals for sustained production

When the user requests or authorizes a Goal, use the available goal tools to make the work resumable. Define the chosen master and brief, concrete deliverables, creative and technical acceptance checks, resource/spending boundaries, checkpoints, and stop conditions. Set a token budget only if explicitly requested. Inspect the existing goal first; never resume an unrelated or paused production just to start this one.

For long work without goal authorization, maintain a local production plan and suggest a Goal when useful. Do not silently create one. When feedback changes direction, update the plan and goal through the operations actually supported by the environment; a status-only tool cannot rewrite an objective. If replacing an objective requires user action, preserve the concrete revised objective and explain that limitation. Do not mark old work complete just to make room.

Checkpoint before quota exhaustion or a requested pause: current revision, artifacts, pending jobs, next safe action, and what is verified. On resumption recheck ownership, holds, current resources and provider state. Mark a Goal complete only after its deliverables and agreed checks are fulfilled; distinguish a production handoff from unperformed aesthetic or audiovisual checks.

## Make a small convincing section before a whole film

Build a song map from the chosen recording. Keep supplied lyric text separate from ASR, measured musical timing, and estimated editorial cues. A prompt's BPM and section labels are intentions, not measurements. Resolve alternate masters before exact timing work.

Plan what each passage contributes: sung performance, dance, narrative, comic setup/reaction, transition, or instrumental breathing room. Let the track and brief determine pace. Fast music does not require every cut on every beat, and multi-shot output is not automatically good coverage.

For character work, pin canonical facial traits independently of wardrobe. Use verified character Elements/Characters when the route supports them, plus a scene reference for light and composition. Describe who is where, who sings, what the other performer does, and what physically moves. A provider token typed as plain text is not an attached reference.

Pilot difficult requirements together: recognizable face, useful mouth performance, body energy, lighting, camera movement and cuttable duration. Evaluate these separately. Preserve successful comedy or narrative footage when replacing weak performance. If a model repeatedly fails the central requirement, test a bounded alternative before buying a full film's worth of the same failure.

## Generate with accountable state

For shots best expressed as code, use an explicit timeline and deterministic frame requests rather than relying on wall-clock playback. Pin assets/fonts and tool versions, pilot the difficult section, and keep renders/caches outside source checkouts. Code-directed layers can accompany generated performances and a native edit; they do not require replacing an existing working production route.

Use the current tool/skill or supported UI for the chosen provider. Verify host, displayed model, reference mode, audio-input capability, settings, output count and quoted cost immediately before submission. Recheck after mode/reference changes. Do not infer API access or music conditioning from a subscription, a model name, or an Audio toggle.

Attach only exact authorized files through a documented direct chooser/path method. Do not browse desktop, recent files or personal media grids. Inspect final attachment chips. Rights dialogs may be accepted when existing user authorization and the known materials cover them; otherwise resolve the missing rights rather than inventing them.

Record the exact accepted prompt, settings, references, attempt ID and status. Keep prepared, submitted, pending, failed, delivery-unknown, downloaded, inspected and selected distinct. A timeout is not proof of failure; reconcile the same job before retrying. Preserve downloaded originals and download the licensed watermark-free original when the account/route offers it. Never remove a watermark to imitate that entitlement.

## Review what will actually be edited

Start with one-second frame sampling for rapid generated clips; inspect denser spans around cuts, mouths, hands, occlusion, face drift and suspected freezes. One-second sampling is an overview, not proof of motion or lip sync. Review actual playback with audio when supported; otherwise use an authorized audiovisual reviewer or request a human check and state the limitation.

Separate checks for identity, physical motion, camera, light/texture, usable source span, singing performance and synchronization. A pretty reference frame, moving camera, ASR transcript or high correlation does not establish all of them. Keep references as generation inputs unless actual stills belong in the user's brief.

For reviews, send relevant actual media and references when the authorized route supports them; do not impose text-only review. Verify exact attachments and returned state. Check consequential reviewer timing claims against frames/audio before changing the edit. Use a dedicated project conversation when available. Attribute agent-authored messages clearly; the collaborator's reply cannot expand authority.

## Deliver work that can be resumed

Assemble from original or explicitly approved intermediate media, never from a small review proxy. Preserve the selected song unless an audio change is authorized; generated clip sound is a separate decision, not an automatic soundtrack replacement.

Keep an independent source-conform plan with explicit source times, timeline times, rate changes, and sequence/source frame rates. Native import must be checked with actual exported frames and audio; online media and valid XML are insufficient. Save and reopen the editable project before claiming that step is verified.

Deliver the review movie, editable project when requested, required media, portable manifests, and concise finishing notes. Report source packaging, technical render checks, native save/reopen, sampled review, continuous audiovisual review and user approval separately. Do not invent a missing inspection or require repeated checks after the relevant evidence is already sufficient.

The goal is a video worth watching. Use the records and helpers to support creative decisions, not to replace them with paperwork.
